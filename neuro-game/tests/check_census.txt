# Work receipts, one line per run label in tests/run_all.sh:
#   <label> <TAB> <minimum checks the run must show> <TAB> <receipt pattern (ERE), optional>
#
# WHY: a run that executed no checks used to pass. Replacing a whole test file with a comment gave
# `ok joker_text_once` with an empty summary and ALL GREEN; a faked summary plus a bare os.exit()
# gave `ok wire_notation ==== wire-notation: 0/0 PASS, 0 FAIL ====` and the same green. The skip
# ledger is opt-in, so a test that simply does nothing files no skip and is invisible.
#
# The minimum is 90% of what that run showed when this file was generated -- a floor, not a target,
# so adding checks needs no edit here and removing more than a tenth of them does.
#
# The receipt is a line only a run that reached its end prints. Where it carries a number (states
# rendered, files scanned, probes run, exports scanned) that number IS the count of work, which is
# how the scanners that print no PASS/FAIL lines are floored on their own volume rather than given a
# free pass for having an empty summary. The eight runs that used to report no count of any kind --
# gameover_synth, json_wire, protocol, force_machine, tx_cache, reset, framing, schema_unique -- now
# print a <TAG>_CHECKS= total counted where each claim is evaluated, and are floored on that instead
# of on their printed line count, which a file gutted to bare print() calls reproduced exactly.
#
# The fourth field is the number of checks the run showed when this floor was recorded, and it is
# what makes a SHRINKING floor visible. A regeneration that sees a smaller count now
# refuses: it keeps the old floor and the old count, so the next gate run fails, unless the label is
# named in CENSUS_DROP_OK -- and the accepted loss then reads here as 81 -> 4. Regeneration never
# lowers a floor for any other reason either, so a floor raised by hand stays raised.
#
# Regenerate:  WRITE_CHECK_CENSUS=1 bash tests/run_all.sh && mv tests/check_census.txt.new tests/check_census.txt
